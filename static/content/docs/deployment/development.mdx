# Development environment

## Start

```bash
docker compose -f compose.dev.yaml up -d
```

The development stack starts one `runtime-agent` named `local-docker` beside `docker-proxy`. Container job claims use that registered runtime endpoint, so the same runtime ownership path is exercised locally even though there is only one Docker daemon.

## Inspect

```bash
docker compose -f compose.dev.yaml ps
docker compose -f compose.dev.yaml logs -f server
docker compose -f compose.dev.yaml logs -f execution-worker
docker compose -f compose.dev.yaml logs -f runtime-agent
```

## Rebuild one service

```bash
docker compose -f compose.dev.yaml up -d --build jobs-service
```

Changes to the shared Docker client package require rebuilding all three
consumers so endpoint migration, mTLS, and certificate reload behavior stay in
sync:

```bash
docker compose -f compose.dev.yaml build runtime-agent workflow-worker execution-worker
docker compose -f compose.dev.yaml up -d --no-deps --force-recreate runtime-agent workflow-worker execution-worker
```

## Reset local state

```bash
docker compose -f compose.dev.yaml down -v
```

This removes databases, Kafka data, and generated certificate volumes. Use it only for an intentional clean reset.
